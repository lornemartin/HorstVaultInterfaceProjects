● Here's the sequence from Server Manager, in order:

  ---
  Step 1 — Install IIS with WebSockets

  From Server Manager → Manage → Add Roles and Features:

  1. Role-based installation → select the local server
  2. Under Server Roles, check Web Server (IIS)
  3. Expand Web Server → Application Development and check:
    - WebSocket Protocol (required for Blazor SignalR)
    - ASP.NET is not needed — leave it unchecked
  4. Click through and install

  No reboot required.

  ---
  Step 2 — Install the .NET 8 Hosting Bundle

  On the server, download and run the .NET 8 ASP.NET Core Hosting Bundle from
  Microsoft. After it installs, run this from an elevated PowerShell to register
  the IIS module:

  & "C:\Windows\System32\inetsrv\appcmd.exe" list module
  /name:AspNetCoreModuleV2

  You should see AspNetCoreModuleV2 listed. If the command returns nothing, run
  iisreset and try again — the hosting bundle installer sometimes needs a reset
  to register.

  ---
  Step 3 — Install PostgreSQL

  Download PostgreSQL 16 (or 17) from postgresql.org. During install:
  - Set a strong superuser (postgres) password — save it somewhere
  - Default port 5432 is fine
  - Include pgAdmin if you want a GUI

  After install, open pgAdmin (or psql) and run:

  CREATE DATABASE horstmfg;
  CREATE USER horstmfg_user WITH PASSWORD 'your-strong-password-here';
  GRANT ALL PRIVILEGES ON DATABASE horstmfg TO horstmfg_user;
  -- Needed for EF Core migrations to create tables:
  ALTER USER horstmfg_user CREATEDB;

  ---
  Step 4 — Create the domain service account

  This is an Active Directory task. On your domain controller (or via RSAT),
  create a user like svc-horstmfg in AD:
  - Password never expires
  - No special group memberships
  - Plain domain user

  Then come back to this server to configure IIS to use it once IIS is set up.

  ---
  Step 5 — Create the local folders

  From an elevated PowerShell on the server:

  New-Item -ItemType Directory -Force "C:\HorstMFG\PDFs\Batches"
  New-Item -ItemType Directory -Force "C:\HorstMFG\PDFs\Schedules"
  New-Item -ItemType Directory -Force "C:\inetpub\horstmfg"

  ---
  Step 6 — Open the firewall

  New-NetFirewallRule -DisplayName "HorstMFG HTTP"  -Direction Inbound -Protocol
  TCP -LocalPort 80  -Action Allow
  New-NetFirewallRule -DisplayName "HorstMFG HTTPS" -Direction Inbound -Protocol
  TCP -LocalPort 443 -Action Allow

  ---
  Step 7 — SSL certificate

  If your domain has an internal CA (AD Certificate Services), request a cert
  for whatever hostname you'll use (e.g. horstmfg.horst.local). If not, create a
  self-signed cert:

  New-SelfSignedCertificate -DnsName "horstmfg.horst.local" -CertStoreLocation
  "cert:\LocalMachine\My"

  With a self-signed cert you'll need to push the public key to Trusted Root on
  each client machine (Group Policy is the clean way).

  ---
  IIS Site Setup (after all the above)

  1. Open IIS Manager
  2. Application Pools → Add Application Pool: name it HorstMFG, .NET CLR
  Version = No Managed Code, Managed Pipeline = Integrated
  3. Set the app pool identity: Advanced Settings → Identity → Custom account →
  DOMAIN\svc-horstmfg
  4. Sites → Add Website: physical path = C:\inetpub\horstmfg, app pool =
  HorstMFG, binding = https/443, select the cert
  5. Add a second binding: http/80 (for the redirect)
  6. In the site's Configuration Editor, set environment variable
  ASPNETCORE_ENVIRONMENT = Production

  ---
  Where are you at with the domain service account — does your sysadmin have
  that created, or do you need to handle it yourself?

❯ in step 3 above, is DOMAIN a place holder, or is that the actual entry?       

● DOMAIN is a placeholder — replace it with your actual Windows domain name (the
  NetBIOS short name, not the full FQDN).

  For example, if your domain is horst.local, the NetBIOS name is likely HORST,
  so you'd enter:

  HORST\svc-horstmfg

  You can confirm your domain's NetBIOS name by running this on any
  domain-joined machine:

  (Get-WmiObject Win32_ComputerSystem).Domain

  That returns the DNS name (e.g. horst.local). The NetBIOS short name is
  usually just the first part before the dot — HORST — but if you're unsure,
  run:

  nltest /dsgetdc:horst.local

  and look for the DC line, which will show the domain name format used for
  authentication.

  1. Create a test page:

  2. Browse to it on the server itself:

  see the heading. If that works, IIS is serving content.

  3. Browse to it from another machine:

  that works, the firewall rules are open and IIS is reachable from the network.
